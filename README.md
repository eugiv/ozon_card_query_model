# Рекомендательная система поисковых кластеров Ozon

Рабочая гибридная система находит **новые малотрафиковые поисковые кластеры
для каждого товара**. Она объединяет смысл запросов и продающие связи каталога,
учится на реальной истории и формирует приоритетный список для SEO-специалиста.

Это публичная копия проекта без исходных бизнес-данных, секретов и обученных
моделей. Тесты используют синтетические данные; для запуска на реальных данных
необходимо отдельно подготовить приватные входы из `config.json`.

**Результат:** `Recall@10` обученного гибрида — **22,85%** против **19,06%**
у контрольного гибрида на одном пуле (**+3,79 п.п.**). Подготовлены **3 530
предложений для 353 товаров**. Это измеренное восстановление будущих продающих
связей; коммерческий эффект изменения карточек оценивается отдельно.

## Где мы находимся

- **1. Постановка задачи и 2. Анализ:** содержание сохранено в
  [презентации для защиты](reports/diploma_task_definition_3slides_v5.pptx),
   адаптированной под приложенные образцы оформления (25 слайдов).
- **3. Методика решения:** реализован полный текстово-поведенческий контур:
  подготовка → поиск → обучение → временная оценка → отдельный финальный refit
  → использование сохранённых моделей. Параметры собраны в `config.json`.
- Обучены CatBoost, семантический адаптер поверх E5 и LightGCN; работает отсев
  явных товарных противоречий. **Разметка и фото не требуются для запуска.**
  [Методика и соответствие критериям этапа](docs/recommender_methodology.md).
- **4. Результаты:** выполнено сравнение методов и вкладов каналов; добавлены
  стресс-проверка сохранённого ранжирования и разбор потерь поиска.
   Исходный `Recall@10` — **22,85%**, шум 15% — **22,41%**, потеря 30% пула —
   **17,61%**. Это диагностическая проверка найденного пула, не всей системы.
- **5. Выводы и 6. Источники:** оформлены в презентации и записке;
  дальнейшие исследования отделены от уже выполненных экспериментов.

## С чего начать подготовку к защите

[Полный гайд по проекту](docs/recommender_methodology.md) — один документ:
методика, объяснение моделей простыми словами, формулы и числовой пример,
интерпретация результатов, карта артефактов, запуск, переобучение,
диагностика ошибок и ответы на вопросы преподавателей. Для чтения вне редактора
есть [тот же гайд в Word](reports/project_guide.docx).

Актуальный результат: [обучение и проверка, 11.10.2026](reports/stage3_20261011.md).
Прочитан полный источник **3 203 109 строк / 2 171 SKU**, 09.01–07.10.2026.
Для оценки обучение отделено от будущего; затем выполнен отдельный полный refit.
Финальный CatBoost: **46 787 строк / 413 SKU**; адаптер: **23 569 сравнений / 589 SKU**;
LightGCN: **10 742 продающие связи / 30 эпох**. Миллионы фактов — не число размеченных
примеров: несопоставленные запросы и неизвестные ответы не превращаются в отрицательные.

На исторической проверке `Recall@10`: текст **9,11%**, контрольный гибрид на том же
пуле **19,06%**, гибрид с обученными каналами **22,85%**. На четырёх более поздних
днях гибрид дал **17,95%**. Сентябрьский период диагностический; короткое октябрьское
окно — дополнительная проверка, не подтверждение устойчивости на всех будущих датах.
Метрика измеряет полноту восстановления продающих связей, не долю всех релевантных фраз.
E5 — предобученная нейросеть, её готовые веса используются без изменения.
На данных проекта обучены residual-адаптер, LightGCN и CatBoostRanker.
По validation выбран гибрид E5, co-sales, адаптера и LightGCN;
CatBoost сохранён как обученный альтернативный ранжировщик.
Текущая архитектура не включает cross-encoder и GraphSAGE; они остаются вариантами
дальнейших экспериментов, а не заявляются обученными компонентами.

## Один рабочий вход

Используйте настроенный интерпретатор PyCharm. Единственный `requirements.txt`
содержит зависимости рекомендателя, одного инструмента материалов и тестов.

```bash
.venv/bin/python src/recommender.py run --config config.json
.venv/bin/python src/recommender.py verify --config config.json
.venv/bin/python src/recommender.py recommend \
  --release reports/stage3_release --as-of 2026-10-11T01:28:00Z \
  --output reports/recommendations_new
```

`run` выполняет все восемь этапов и возобновляет только результаты с совпадающими
входами и параметрами. `verify` проверяет файлы и заново считает метрики без
обучения. `recommend` использует готовый выпуск, не переобучает модели.
Он воспроизводит выдачу по входам, закреплённым в выпуске: новая дата `as-of`
не загружает свежий трафик или текст из ClickHouse. Для новых входов нужен
новый эксперимент; `finalize` — отдельная команда финального переобучения.
Пути относительны файлу конфигурации. Для нового эксперимента замените все
выходные пути: чужие или изменённые результаты не перезаписываются.

Часть 4 использует сохранённые проверочные прогнозы **без обучения**:

```bash
.venv/bin/python src/recommender.py results \
  --evaluation reports/stage3_evaluation --output reports/stage4_results_new \
  --seed 7 --repetitions 3 --bootstrap-iterations 2000
```

Готовый результат уже находится в `reports/stage4_results/`. Команда выше
создаёт новую папку: повторная запись в существующую запрещена.
Результат — только `metrics.json` и манифест, без новых копий CSV и моделей.
Правильные ответы и веса не меняются. Разобраны шум оценок, выбросы счётчиков
и потеря кандидатов; это **не** проверка обучения на испорченных данных или
опечаток в тексте. Компактные агрегаты включены в сдаваемый публичный снимок.

Подключение к ClickHouse — через **`.env` этого проекта** (`DBT_CLICKHOUSE_*`),
только чтение. `OZON_CARD_ENV` позволяет выбрать иной файл; окружение имеет
приоритет. Поддерживаются CA и клиентские сертификаты, проверка TLS не отключена.
Секреты и исходные бизнес-данные не публикуйте.

## Структура без путаницы

Рабочий код — **9 модулей**, без отдельных файлов для мелких помощников:

| Файл в `src/` | За что отвечает |
|---|---|
| `recommender.py` | Единый запуск и проверка всех этапов |
| `cluster_data.py` | ClickHouse, тексты карточек, словарь, агрегация и контрольные суммы |
| `cluster_recommender.py` | E5-кодирование и поиск кандидатов |
| `dormant_learning.py` | CatBoost, объединение рангов и расчёт метрик |
| `semantic_adapter.py` | Обучение семантического адаптера E5 |
| `graph_learning.py` | Обучение LightGCN |
| `full_history_recommender.py` | Временные эксперименты, сравнение каналов и их вклада |
| `finalize_recommender.py` | Финальное обучение и выдача сохранённых моделей |
| `seo_recommendation_policy.py` | Проверка текста, явных противоречий и короткий список |

**Один отдельный инструмент** — `tools/defense.py`: пересборка презентации,
записки, личного гайда и агрегированного снимка. В `src/` нет оформления слайдов.
Назначение остальных папок:
- `data/` — датированные входы, словарь и E5-векторы.
- `reports/<run>/` — неизменяемые модели, прогнозы, метрики и контрольные суммы.
- `tests/` — в том числе настоящее небольшое обучение, изоляция будущего,
  полнота знаменателей, фильтры и возобновление расчётов.

Текущая очередь: `reports/stage3_release/recommendations_for_review.csv`
(**3 530 предложений / 353 SKU**). Для каждой строки доступны товар, кластер,
продающий ориентир, прежние просмотры, приоритет и свидетельства товарного отсева.
Все большие артефакты остаются приватными локально. Старые генераторы и
неиспользуемые контуры удалены; модели для оценки и выпуска сохранены раздельно.

### Почему в SEO-политике есть правила

`seo_recommendation_policy.py` **не подменяет ML**. Он не содержит заранее
заданных рекомендаций по SKU. Нейросети и ранжирование находят запросы;
правила не дают предложить товару чужой бренд, другой объём или явно иной материал.
Бренды берутся из загруженных карточек. Лексический словарь ограничений явно
задан и имеет версию: это проверяемая защита, а не скрытые обученные ответы.
Проверка наличия точной фразы также находится здесь. Удаление модуля уберёт
эти ограничения, поэтому он нужен. Повторяющаяся обработка правил упрощена.

`unique_view_users` — карточку **увидели**, не кликнули.
Мало просмотров не доказывает отсутствие фразы в SEO; отсутствие будущего
заказа не доказывает нерелевантность. Текущая выдача остаётся `review`.
Проверка прироста продаж — последующая бизнес-задача, не замена оценки рекомендателя.

Пересборка готовых материалов не требует ClickHouse или повторного обучения:

```bash
.venv/bin/python -m tools.defense presentation
.venv/bin/python -m tools.defense note
.venv/bin/python -m tools.defense guide
```

Если изменились сохранённые результаты из `config.json`, обновите публичный
снимок и презентацию:

```bash
.venv/bin/python -m tools.defense summary --config config.json \
  --results reports/stage4_results/metrics.json
.venv/bin/python -m tools.defense presentation
```

Без обновления снимка пересборка использует сдаваемые агрегаты,
не требует приватных артефактов и не запускает обучение.

Для проверки размеров используются локальные Arial, DejaVu Sans или Liberation
Sans; готовые файлы открываются без Python. Цвета, сетка и текст выступления
в инструменте материалов — оформление, а не параметры ML. Значения метрик,
число товаров и обучающих примеров читаются из JSON, а не задаются вручную.

## Что сдавать

Исходный комплект: `README.md`, `.gitignore`, `config.json`, `requirements.txt`,
`src/`, один файл в `tools/`, `tests/`, два документа в `docs/` и шесть публичных
файлов в `reports/`: презентация, записка, личный гайд, `analysis_slides_data.json`,
`experiment_summary.json`, `stage3_20261011.md`. JSON — источники графиков, не лишние версии.

**Не отправляйте ZIP всей рабочей папки:** `.env`, сертификаты, `.venv/`, реальные
данные, веса и полные CSV остаются приватными. Для демонстрации реального запуска
они передаются отдельно по согласованному доступу, с исходными контрольными суммами.
Тесты работают на синтетических данных без ClickHouse и обучают настоящие модели;
это проверка работоспособности, не доказательство качества на искусственной выборке.

Восемь папок из `config.json` — не восемь старых версий. Это контрольный эксперимент,
проверочные адаптер и граф, оценка и сравнение компонентов, финальные адаптер и граф,
один итоговый выпуск. Они нужны для воспроизведения сравнения и проверки обучения
без будущих ответов. Проверочные модели обучены до validation; финальные — по 07.10.
Удаление первых ради короткого дерева лишило бы нас проверяемого эксперимента.

Существующие модели и их манифесты не переписываются при объединении кода:
исторические хэши исходников остаются свидетельством версии обучения. Новые запуски
записывают уже сокращённый набор модулей. Публичная версия содержит исходники,
документацию и агрегаты; приватные модели и полные выгрузки в неё не входят.

```bash
.venv/bin/python -m pytest -q tests
```
