# Приоритизация поисковых запросов Ozon

Модель оценивает, по каким запросам у карточки вероятнее заказ в следующие
28 дней. Она помогает расставить запросы по приоритету, но не доказывает,
что добавление или удаление фразы изменит продажи.

Кандидаты фиксируются только по прошлому окну. Будущие заказы и частота
используются как ответ, но не влияют на состав test-выборки.

Исторических снимков текста карточек пока нет. Поэтому текстовые признаки
отключены: benchmark использует только доступную на дату решения историю
поисков, переходов и заказов.

## Как запустить

Учётные данные читаются из `.env` репозитория `clickhouse_dbt`
(`DBT_CLICKHOUSE_*`). Файл с паролем сюда не копируется.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python src/train.py
```

Финальный test cutoff зафиксирован на `2026-09-25`. Для нового независимого
экзамена дату нужно передать явно:

```bash
.venv/bin/python src/train.py --cutoff 2026-11-20
```

## Решения

- `keep` — запрос уже приносил заказы или модель уверенно ожидает заказ;
- `review` — данных недостаточно для автоматического решения;
- `remove_candidate` — было достаточно поисков и переходов, но оценка
  будущего заказа низкая.

`remove_candidate` — только очередь на ручную проверку. Скрипт не меняет
карточки и не вызывает API Ozon.

## Что проверяется

- CatBoost без балансировки классов и логистическая baseline-модель;
- правило «заказ уже был» и baseline «оставить всё»;
- PR-AUC, ROC-AUC, Brier score, log-loss и ошибка калибровки;
- итоговая политика после правил для sparse-карточек и объединения тем;
- rolling backtests;
- 95% интервалы через bootstrap целых SKU;
- отдельные пороги для уверенного `keep` и безопасного
  `remove_candidate`.

Модель для текущих рекомендаций обучается на всех созревших старых блоках.
Последний созревший блок используется для калибровки.

## Артефакты одного запуска

Каждый запуск сначала собирается во временной папке, затем атомарно
публикуется в `reports/runs/<artifact_id>/`. `reports/latest.json` указывает
на последний полностью завершённый запуск.

- `metrics.json` — окна, метрики, интервалы и ограничения;
- `test_predictions.csv` — построчная проверка полного pipeline;
- `model_curves.csv` — точки ROC и precision-recall;
- `recommendations.csv` и `recommendations.xlsx` —
  одинаковый список текущих рекомендаций;
- `deployment_model.cbm` и `deployment_calibrator.joblib` —
  рабочая модель и калибратор.
- `manifest.json` — Git SHA, версии пакетов и SHA-256 всех файлов запуска.

Для совместимости основные файлы копируются в `reports/` только после
успешной публикации запуска. Журнал экспериментов хранится в локальном
MLflow (`mlflow.db`). Облачный аккаунт не используется: в журнал могут
попадать тексты запросов.
